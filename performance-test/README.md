# Performance Test

`performance-test` contains reproducible K6 baselines for EveryPicFound search flows.

## Preconditions

- Start the backend with one of these profile files:
  [application-perf-baseline.yml](E:/EveryPicFound/everypicfound-backend/src/main/resources/application-perf-baseline.yml)
  [application-perf-cache-miss.yml](E:/EveryPicFound/everypicfound-backend/src/main/resources/application-perf-cache-miss.yml)
  [application-perf-cache-hit.yml](E:/EveryPicFound/everypicfound-backend/src/main/resources/application-perf-cache-hit.yml)
- The older [application-pref-baseline.yml](E:/EveryPicFound/everypicfound-backend/src/main/resources/application-pref-baseline.yml) is kept for compatibility, but `perf-*` is the naming used by the current K6 test set.
- Prometheus should scrape `http://localhost:8080/actuator/prometheus`.
- The generated image query dataset is stored under `performance-test/data/generated-query-images/` and is not part of measured time.

## Query Inputs

- Text search uses `data/text-queries.json` plus deterministic natural-language expansion in the full-page text script.
- Image and hybrid search use `data/image-query-manifest.json`.
- The manifest is generated by:

```powershell
powershell -ExecutionPolicy Bypass -File performance-test/scripts/generate-query-images.ps1 -Count 24
```

## Common Environment Variables

- `BASE_URL`: defaults to `http://127.0.0.1:8080`
- `PROFILE`: defaults to `baseline`
- `VUS`: defaults to `10`
- `DURATION`: defaults to `3m`
- `TOP_K`: defaults to `30`
- `QUERY_MODE`: `fixed-pool` for cache-hit style reuse, `unique` for cache-miss style hybrid text variation

## Baseline Commands

Text search:

```powershell
k6 run performance-test/scripts/text-search-baseline.js -e VUS=10 -e DURATION=3m -e TOP_K=30
```

Text search + full image loading:

```powershell
k6 run performance-test/scripts/text-search-image-access-baseline.js -e VUS=10 -e DURATION=30s -e TOP_K=30
```

Image search:

```powershell
k6 run performance-test/scripts/image-search-baseline.js -e VUS=5 -e DURATION=3m -e TOP_K=30
```

Image search + full image loading:

```powershell
k6 run performance-test/scripts/image-search-image-access-baseline.js -e VUS=5 -e DURATION=30s -e TOP_K=30
```

Hybrid search:

```powershell
k6 run performance-test/scripts/hybrid-search-baseline.js -e VUS=5 -e DURATION=3m -e TOP_K=30
```

Hybrid search + full image loading:

```powershell
k6 run performance-test/scripts/hybrid-search-image-access-baseline.js -e VUS=5 -e DURATION=30s -e TOP_K=30
```

## Metrics

Search-only scripts keep `http_req_duration`, `business_failures`, and K6 summary percentiles separate from page metrics.

Full-page scripts emit:

- `page_search_duration`
- `image_access_duration`
- `page_image_batch_duration`
- `page_total_duration`
- `search_iterations`
- `successful_searches`
- `image_batches`
- `returned_image_items`
- `image_requests`
- `search_failures`
- `image_failures`
- `page_failures`

## Result Files

Recommended filename template:

```text
<scenario>-<profile>-vu<VUS>-<duration>-topk<TOP_K>.<json|txt>
```

Examples:

```text
text-search-baseline-baseline-vu10-3m-topk30.json
image-search-image-access-baseline-vu5-30s-topk30.txt
```

## Cache Scenarios

- Baseline:
  backend uses `application-perf-baseline.yml`
  K6 uses `PROFILE=baseline`
- Cache miss:
  backend uses `application-perf-cache-miss.yml`
  K6 should prefer unique inputs, for example `QUERY_MODE=unique` on hybrid search and broad query variation elsewhere
- Cache hit:
  backend uses `application-perf-cache-hit.yml`
  K6 should use `QUERY_MODE=fixed-pool` so the same small query pool is reused
- `application-perf-cache-miss.yml` and `application-perf-cache-hit.yml` use different Redis key prefixes so the two runs do not contaminate each other.
